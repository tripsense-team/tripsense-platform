# Decisions

| Decision                                                              | Rationale                                                                                                                                                                                                | Alternatives rejected                                                                                       |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| P0 is a release blocker before rail work                              | The user cannot share an owned trip reliably otherwise.                                                                                                                                                  | Hiding the composer error or replacing it with client data.                                                 |
| Keep current Trip list first                                          | Its response shape already matches the picker and Trip owns owner filtering.                                                                                                                             | Duplicating the same list in Social.                                                                        |
| Separate list and preview errors                                      | Preview executes immediately after selection and currently shares an error state with listing.                                                                                                           | Reporting every failure as "cannot load trips".                                                             |
| Public profile is a User contract                                     | Social cannot safely derive public identity from email/private profile API.                                                                                                                              | Reusing `/api/users/profile/{id}`.                                                                          |
| Social owns follows                                                   | Following is Community graph behavior and should not couple User persistence.                                                                                                                            | User table or cross-service FK.                                                                             |
| Weather waits for canonical destination                               | `destinationPlaceId`/Place identity is not yet an approved public contract.                                                                                                                              | Weather by free-text destination or the AI mock.                                                            |
| First destination trend is public-share popularity, not actual visits | Current Social data proves publication, not a person's location or arrival.                                                                                                                              | Calling shares “people going there today”.                                                                  |
| Trend aggregate stays in Social for public shares                     | Social owns post visibility/moderation and can update its own aggregate transactionally after H supplies a safe canonical reference.                                                                     | Grouping `destinationName`, querying Trip/Place databases or creating a new service for this bounded slice. |
| Actual-travel trends wait for Context                                 | Opt-in, event semantics and privacy controls are required before aggregating travel activity.                                                                                                            | Synchronous Trip reads or inferring presence from dates/posts.                                              |
| Community creator identity is automatically available                 | The approved product direction is that normal accounts appear in Community without a discovery opt-in. User Service provides a display name/avatar; a generated non-email handle covers legacy accounts. | Hiding all accounts by default or exposing email-derived names.                                             |
| Creator suggestions prioritize established creators                   | The approved product direction is to show accounts with more followers first, with stable secondary ordering.                                                                                            | Opaque AI ranking or a random list.                                                                         |

## Review findings

- **BLOCKER:** Current profile API exposes email/private fields; it cannot be used for creator discovery.
- **HIGH:** The UI must capture the actual authenticated My Trips/preview response before declaring the backend list broken. The browser automation environment was unavailable during planning, so this remains a P0 reproduction gate.
- **HIGH:** Social's Trip client catches the wrong response exception family, risking real Trip errors becoming `503`.
- **HIGH:** A fixed `size=20` picker can silently omit valid trips.
- **HIGH:** Weather before canonical public destination risks incorrect results and private-location disclosure.
- **MEDIUM:** Gateway Social rate limiting is disabled by default and must be configured before discovery/weather writes/reads are exposed.
- **BLOCKER:** `GET /api/social/**` is currently broadly anonymous. Explicit authenticated matcher ordering and Gateway regression tests are required for personalized discovery routes.
- **HIGH:** Current Social author storage includes email-derived display data. Public creator cards and legacy author output require an allowlisted User display-name/avatar projection; existing private profile responses cannot be reused.
- **HIGH:** Blocking is not yet an owned, defined contract. V1 excludes unavailable/non-public creators; block-based filtering is deferred until a blocking owner and semantics are approved.
